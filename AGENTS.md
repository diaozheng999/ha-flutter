# ha-flutter

Custom Home Assistant frontend built with Flutter, targeting Android and Windows.
iOS and macOS platform directories are present but builds require Xcode on a Mac.

## Commit Messages

All commits must follow this format:

```
type: concise description (<tool>, <model>)
```

**Types:** `feat` | `fix` | `refactor` | `docs` | `test` | `chore` | `build` | `ci`

Keep the description short and imperative (e.g. "add login screen", not "added login screen").

The trailer `(<tool>, <model>)` identifies the agent tool and model that produced the commit.
**Update BOTH the tool and the model to match what actually produced the commit** — the placeholder
`(claude-code, sonnet-4.6)` is an example only, not a default. 

*Note: For the `pi` tool, model is not exposed, so the trailer is simply `(pi)` instead of `(pi, model)`.*

Known values:

| Tool | Typical Models | Example Trailer |
| :--- | :--- | :--- |
| `antigravity` | `gemini-3.5-flash`, `gemini-3.5-pro` | `(antigravity, gemini-3.5-flash)` |
| `cursor` | `cursor-small`, `cursor-fast`, `claude-3-5-sonnet` | `(cursor, claude-3-5-sonnet)` |
| `claude-code` | `sonnet-4.6`, `opus-4.2` | `(claude-code, sonnet-4.6)` |
| `zcode` | `glm-5.2`, `glm-4.6` | `(zcode, glm-5.2)` |
| `codex` | `gpt-5`, `o4`, `gpt-4o` | `(codex, gpt-4o)` (used for ChatGPT/Codex) |
| `trae` | `claude-3-5-sonnet`, `gpt-4o` | `(trae, claude-3-5-sonnet)` |
| `opencode` | `deepseek-coder`, `qwen-2.5-coder` | `(opencode, deepseek-coder)` |
| `pi` | *(None)* | `(pi)` (no model exposed) |
| `copilot` | `gpt-4o`, `claude-3-5-sonnet` | `(copilot, gpt-4o)` (used for VS Code Copilot) |

If you're unsure of your tool/model, infer from the environment or runtime metadata; do not default to the example. The historical commits used `(claude-code, sonnet-4.6)` and should not be retroactively edited.

## Development Setup

After cloning, run the appropriate setup script to install all agent tooling:

```
# Windows
scripts\setup.ps1

# Linux / macOS
bash scripts/setup.sh
```

The setup script installs dependencies, initialises OpenSpec (prompting interactively to select which AI tools to configure, or non-interactively if a tools parameter is passed), and configures project-scope MCPs.
Re-run it any time skills or MCP commands seem missing.

## Skill & Tool Management

Agent tools are managed as **local npm devDependencies** — not installed globally.

- All agent tool packages are declared in `package.json` under `devDependencies`.
- Installed artifacts and agent configs (e.g. `.agent/`, `.agents/`, `.claude/`, `.codex/`, `.cursor/`, `.opencode/`, `.pi/`, `.zcode/`, `node_modules/`) are **gitignored**. Never commit them — they are regenerated by the setup script.
- After setup, the following slash commands are available in supporting agents (e.g., Claude Code, Zcode, OpenCode, Codex):
  - `/opsx:propose`, `/opsx:explore`, `/opsx:apply`, `/opsx:sync`, `/opsx:archive` — OpenSpec workflow
  - `/run`, `/verify`, `/code-review` — standard project skills

**To add a new agent tool:**
1. Add its npm package to `package.json` devDependencies.
2. Add the initialisation command to both `scripts/setup.ps1` and `scripts/setup.sh`.
3. Document it in this section.

**Bootstrap check:** if `/opsx:*` or other expected slash commands are unavailable, run the setup script for your OS and restart your agent runtime (e.g., Claude Code, Cursor, your IDE).

## MCP Servers

This project uses the **homeassistant-custom** MCP to interact with the Home Assistant instance during development.
It is typically configured at the user or IDE level (e.g., via `claude_desktop_config.json` for Claude Desktop/Code, or settings configs for Cursor, VS Code, etc.). 

If you need to configure it manually for your environment, you can add it via CLI or settings. For example, in Claude Code/Desktop:
```bash
claude mcp add homeassistant-custom <server-command> --env HA_URL=<url> --env HA_TOKEN=<token>
```

## Flutter

**Target platforms:** Android, Windows
**Deferred platforms:** iOS, macOS (require Xcode; directories are present for future use)

Run `flutter doctor` to verify your toolchain. `flutter build windows` should succeed on this machine.
iOS and macOS builds are expected to fail without Xcode — that is intentional.

## OpenSpec

Spec files live in `openspec/`. Use the `/opsx:propose` slash command (or corresponding workflow in your agent) to start a new feature spec.
The `openspec/config.yaml` defines project context injected into every spec prompt.
